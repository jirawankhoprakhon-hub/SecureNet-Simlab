MODULE 1 : ACCESS CONTROL PROTOCOL Physical Layer

หลักการและการต่อสายสัญญาณ Wiegand 26-bit[cite: 1, 5]

ชุดสายสัญญาณ 3 เส้นหลัก[cite: 5]

  • • DATA0 (เขียว): ใช้ส่งพัลส์สำหรับบิตข้อมูล `0`[cite: 5]
  • • DATA1 (ขาว): ใช้ส่งพัลส์สำหรับบิตข้อมูล `1`[cite: 5]
  • • GND (ดำ): สายกราวด์ร่วมอ้างอิงแรงดันไฟฟ้า[cite: 5]

ลักษณะทางไฟฟ้า (Signal Timing)[cite: 5]

สภาวะปกติ (Idle) แรงดันจะแช่อยู่ที่ระดับ +5V (HIGH)[cite: 5] เมื่อต้องการส่งบิตข้อมูล แรงดันจะถูกดึงลงกราวด์ 0V (Active-LOW) เป็นพัลส์สั้นๆ กว้างประมาณ 50–100 µs[cite: 5]

จุดเชื่อมโยงกับหน้าปฏิบัติการ SimLab

📊 สังเกตรูปคลื่นพัลส์ตกบนหน้าจอ Oscilloscope เสมือน เปรียบเทียบรูปคลื่นจริงที่ได้จากการวัดด้วยเครื่องมือวัดอิเล็กทรอนิกส์
💡 ให้นักเรียนสังเกตว่าเมื่อส่งบิต 0 และ 1 เส้นกราฟสีใดจะตกลงมาที่ 0V

พฤติกรรมของข้อมูล: บิต 0 จะกลายเป็น 1 และบิต 1 จะกลายเป็น 0 ข้อมูลในเฟรมจะกลับด้านทั้งหมด ทำให้หมายเลขบัตรและรหัสหน่วยงานอ่านค่าไม่ได้
การตัดสินใจของตู้ควบคุม: ระบบคำนวณผลรวม Parity Check ล้มเหลว ตู้คอนโทรลเลอร์จะปฏิเสธสิทธิ์ (Access Denied) และไม่ส่งไฟไปสั่งปลดล็อกกลอนประตู
MODULE 2 : SERIAL BUS ARCHITECTURE Differential Signal

โครงข่ายบัสสื่อสาร RS-485 (Half-Duplex)[cite: 1, 2]

การส่งสัญญาณแบบผลต่างแรงดัน[cite: 2]

วัดผลต่างแรงดันระหว่างสายคู่บิดเกลียว (Va - Vb)[cite: 2] สามารถหักล้างสัญญาณรบกวนภายนอก (Common-Mode Noise) ได้ดีเยี่ยม[cite: 1] และเดินสายได้ระยะทางไกลสูงสุดถึง 1,200 เมตร[cite: 5]

กฎเหล็กการเดินสาย Daisy Chain[cite: 2, 3]

ต้องต่อพ่วงอุปกรณ์จาก Master วิ่งไปหา Slave ตัวที่ 1, 2, 3 เรียงเป็นแถวแบบ Daisy Chain[cite: 2, 3] ห้ามต่อแยกกิ่งรูปดาว (Star) เพราะจะทำให้เกิดคลื่นสะท้อนกวนข้อมูล[cite: 2, 3]

หน้าที่ของตัวต้านทาน 120Ω ปิดท้ายบัส[cite: 3]

ติดตั้งที่ หัวและท้ายสุดของสายบัส เพื่อทำหน้าที่ Termination[cite: 3] ดูดซับพลังงานสัญญาณไม่ให้สะท้อนกลับ (Signal Reflection)[cite: 3]

ผลกระทบของ Baud Rate Mismatch:[cite: 1] หาก Master และ Slave ตั้งความเร็วไม่ตรงกัน (เช่น 9600 vs 19200 bps) บนหน้าจอ Serial Monitor จะปรากฏแต่ข้อมูลขยะ (Frame Error)[cite: 1]
MODULE 3 : IP SURVEILLANCE NETWORK TCP/IP & PoE

ระบบกล้องวงจรปิด IP และการจ่ายไฟ PoE[cite: 1, 4]

1. สายสัญญาณ & RJ45[cite: 1, 4]

มาตรฐานสายแลน UTP[cite: 4]

เรียงสีตามมาตรฐาน T568B เข้าหัวต่อ RJ45 สำหรับเชื่อมต่อกล้อง IP เข้ากับ Switch PoE[cite: 1, 4]

2. ระบบจ่ายไฟ PoE[cite: 1, 4]

Power over Ethernet[cite: 1, 4]

จ่ายแรงดันไฟ DC ไปบนสายแลนคู่เดียวกับการส่งข้อมูล ทำให้ไม่ต้องเดินสายไฟ 220V หรืออแดปเตอร์แยกต่างหากที่ตัวกล้อง[cite: 4]

3. การตรวจเช็คสาย[cite: 1]

คำสั่ง Ping (ICMP)[cite: 1]

ทดสอบการนำกระแสสัญญาณและความต่อเนื่องของสายแลน และตรวจเช็คสถานะการออนไลน์ของกล้องก่อนขึ้นบันทึกภาพ[cite: 1]

ข้อควรระวังสำคัญ: ปัญหา IP Conflict (หมายเลขไอพีชนกัน)

หากตั้งค่า IP ของกล้องซ้ำกับเครื่องอื่นในวงแลน สวิตช์เครือข่ายจะสับสนตาราง MAC Address ส่งผลให้ภาพหลุด ดับ หรือติดๆ ดับๆ ตลอดเวลา

MODULE 3 : VIDEO PROTOCOLS Open Standards

การรวมภาพข้ามยี่ห้อด้วย ONVIF และ RTSP[cite: 7]

🌐 มาตรฐานเปิด ONVIF (Profile S)[cite: 7]

ช่วยให้กล้อง IP และเครื่องบันทึก NVR ต่างค่ายสามารถค้นหากันเจอในวงแลนอัตโนมัติผ่านพอร์ต UDP 3702 (WS-Discovery) โดยไม่ต้องพึ่งพาซอฟต์แวร์เฉพาะยี่ห้อ[cite: 7]

▶️ โปรโตคอล RTSP (Real-Time Streaming)[cite: 7]

โปรโตคอลมาตรฐานสำหรับดึงสตรีมวิดีโอสดผ่าน พอร์ต 554 ใช้สำหรับส่งต่อภาพไปยังเซิร์ฟเวอร์ AI หรือระบบ VMS[cite: 1, 7]

โครงสร้าง RTSP Stream URL ที่ช่างต้องรู้จัก:[cite: 7]
rtsp://admin:12345@192.168.1.10:554/live/ch0[cite: 7]
ขั้นตอน Handshake: OPTIONS ➔ DESCRIBE ➔ SETUP ➔ PLAY[cite: 7]
MODULE 4 : SMART EVENT LINKAGE IoT & AI

กล้อง Edge AI และการสั่งงานข้ามระบบผ่าน MQTT[cite: 1, 6]

กล้องตรวจจับอัจฉริยะ (Edge AI)[cite: 1]

ประมวลผลวิเคราะห์ภาพภายในตัวกล้อง เช่น การจดจำใบหน้า (Face Recognition) และการอ่านป้ายทะเบียน (LPR) โดยไม่ต้องส่งไฟล์วิดีโอขนาดใหญ่ไปรันบนคลาวด์[cite: 1]

โปรโตคอล MQTT (Publish / Subscribe)[cite: 6]

สถาปัตยกรรมส่งข้อความน้ำหนักเบา กินแบนด์วิธต่ำ เมื่อเกิดเหตุการณ์ กล้องจะ Publish ข้อความไปยัง Broker เพื่อสั่งการอุปกรณ์อื่นในระบบพร้อมกันทันที[cite: 6]

ตัวอย่าง JSON Message Payload:
{
  "device": "Gate-AI-Camera",
  "event": "FACE_RECOGNITION",
  "name": "Somchai (Staff)",
  "confidence": 98.5,
  "action": "UNLOCK_DOOR"
}
ข้อมูลแบบคู่คีย์-ค่า (Key-Value) เป็นมาตรฐานสากลที่อุปกรณ์ IoT ทุกระบบเข้าใจตรงกัน
MODULE 4 : LIFE SAFETY INTERLOCK NFPA Standards[cite: 1]

มาตรฐานความปลอดภัยระบบล็อค และอินเตอร์ล็อกหนีไฟ[cite: 1]

มาตรฐานประตูหนีไฟ

ระบบ Fail-Safe (ตัดไฟแล้วปลดล็อก)[cite: 1]

กลอนแม่เหล็กไฟฟ้า (Magnetic Lock) ต้องใช้ไฟเลี้ยงในการดูดล็อก[cite: 1] เมื่อเกิดเหตุไฟฟ้าดับ หรือสัญญาณเตือนเพลิงไหม้ดัง ระบบต้องตัดไฟเพื่อให้ประตูเปิดออกได้ทันที เพื่อความปลอดภัยในชีวิต[cite: 1]

มาตรฐานห้องมั่นคง

ระบบ Fail-Secure (ตัดไฟแล้วยังล็อก)[cite: 1]

กลอนสลักไฟฟ้าหรือกลอนดิจิทัลของห้องเซิร์ฟเวอร์หรือตู้เซฟ เมื่อไฟฟ้าดับ ประตูจะยังคงล็อกแน่นหนาเพื่อป้องกันการบุกรุก[cite: 1] (ต้องใช้กุญแจกลไกไขฉุกเฉิน)

การต่อวงจรตัดไฟผ่านตู้ Fire Alarm (Fire Interlock Interface)[cite: 1]

หน้าสัมผัสของตู้ดับเพลิงจะถูกต่อแบบ Normally Closed (NC) อนุกรมคั่นสายไฟเลี้ยงกลอนประตู เมื่อเกิดเหตุควันไฟ รีเลย์จะตัดวงจรไฟทันทีโดยไม่ต้องรอคอนเฟิร์ม[cite: 1]

SUMMARY : PROTOCOL MATRIX Review

ตารางสรุปเปรียบเทียบ 4 โปรโตคอลหลักในงานช่าง

โปรโตคอล สื่อกลาง / รูปแบบสัญญาณ อุปกรณ์หน้างานหลัก จุดเน้นการตรวจซ่อม
Wiegand[cite: 5] พัลส์ Active-LOW (D0/D1)[cite: 5] เครื่องอ่านบัตร RFID ➔ ตู้คอนโทรล[cite: 1, 5] เช็คสาย D0/D1 สลับขั้ว, Parity Error
RS-485[cite: 2] แรงดันผลต่าง (Differential A/B)[cite: 2] บัสสแกนลายนิ้วมือ / กล้อง PTZ[cite: 1] ต่อ Daisy Chain[cite: 2, 3], ใส่ 120Ω[cite: 3], ตั้ง Baud Rate[cite: 1]
TCP/IP & RTSP[cite: 1, 7] แพ็กเก็ตแลน RJ45 (Port 554)[cite: 1, 4, 7] กล้อง IP Camera ➔ เครื่อง NVR[cite: 1] เช็คสาย Ping[cite: 1], ป้องกัน IP ชนกัน, เช็ค ONVIF[cite: 7]
MQTT / JSON[cite: 6] ข้อความ Pub/Sub ผ่าน Broker[cite: 6] กล้อง AI ➔ รีเลย์ปลดล็อกประตู Fail-Safe[cite: 1] ความถูกต้องของ Topic และโครงสร้าง JSON
